# 종목 추천 모델 (Stage 2: 멀티팩터 스코어링)

KOSPI / KOSDAQ / NASDAQ 중 시장을 선택하면 단기·중기·장기·종합 각 상위 5개 종목을 추천하는 정량 모델입니다.

## 실행 방법 (웹 대시보드)

```bash
# 의존성 설치
pip install -r requirements.txt

# 웹 대시보드 (추천 + 포트폴리오 통합)
export DASH_PIN=1234              # 권장: 공개 IP에서 운영 시 PIN 설정 (미설정 시 인증 없음)
python app.py                     # http://서버IP:8899
python app.py --demo              # 합성 데이터로 화면 확인 (API 불필요, 장부 수정 불가)
python app.py --port 9000         # 포트 지정
```

브라우저에서 접속하면 **종목 추천** 탭과 **내 포트폴리오** 탭으로 구성된 대시보드가 나옵니다.
- 종목 추천: 시장 선택 → [추천 실행] 버튼 → 단기/중기/장기/종합 상위 5개 표시.
  분석은 서버 백그라운드에서 돌고 화면은 몇 초마다 진행 단계를 갱신하므로,
  수십 분 걸리는 첫 실행도 브라우저 타임아웃 없이 기다릴 수 있습니다 (창을 닫아도 계속 진행).
  완료된 결과는 디스크에 저장되어 재접속·다른 기기·서버 재시작 후에도 다시 보입니다.
- 포트폴리오: 매수/매도 기록 → [조회] 버튼 → 현재가·평가손익·수익률 표시

오라클 서버에서 실행할 경우 방화벽(인그레스 규칙)에서 8899 포트를 열어야 외부 접속 가능합니다.

### CLI로도 실행 가능

```bash
python recommend.py --market KOSPI              # 터미널에 추천 결과 출력
python dashboard.py                             # 터미널에 손익 1회 출력
```

## 투자 손익 대시보드 (조회형)

추천 종목을 주식앱에서 실제 매수한 뒤, 매수 내역을 장부에 기록해두면
**[조회]를 누르는 시점에만** 현재가를 가져와 평가손익을 보여줍니다 (상시 폴링 없음).

```bash
# 1) 매수/매도 내역 기록 (주식앱 체결 내역을 그대로 옮기면 됨)
python portfolio.py add  --market KOSPI  --ticker 005930 --qty 10 --price 71000 --name 삼성전자
python portfolio.py add  --market NASDAQ --ticker AAPL   --qty 5  --price 230.5 --name Apple
python portfolio.py sell --market KOSPI  --ticker 005930 --qty 3  --price 75000
python portfolio.py list        # 거래 내역
python portfolio.py holdings    # 보유 현황 (시세 조회 없음)

# 2) 손익 조회
python dashboard.py             # 터미널에 1회 조회 결과 출력
python dashboard.py --web       # http://127.0.0.1:8899 — 브라우저 [조회] 버튼으로 갱신
python dashboard.py --demo      # 가상 장부 + 합성 시세로 화면 확인 (API 불필요)
```

- **시세 출처**: 한국은 네이버 금융 실시간 시세(실패 시 pykrx 종가 폴백),
  나스닥은 Yahoo(약 15분 지연). 조회 버튼을 누른 순간에만 1회 조회합니다.
- **표시 항목**: 종목별 평단·현재가·전일比·평가금액·평가손익·수익률,
  시장별 합계(원/달러 분리), 매도로 확정된 실현손익.
- **평균단가**: 이동평균법 — 추가 매수 시 평단 갱신, 매도 시 평단 유지 + 실현손익 기록.
- 장부는 `data/portfolio.json`에 저장됩니다 (git 추적 제외).

- `DART_API_KEY`가 없어도 실행은 됩니다 — ROE/부채비율/영업이익률(퀄리티 팩터)만 빠진 채
  나머지 팩터로 점수가 계산됩니다 (가중치 자동 재정규화).
- 첫 실행은 데이터 수집 때문에 오래 걸립니다 (KOSPI 전 종목 시세 순회 수십 분).
  수집 결과는 `.cache/`에 저장되어 **같은 기준일 재실행 시 즉시 로드**됩니다.
- 나스닥은 기본적으로 종목 리스트 앞 500개만 수집합니다 (`NasdaqAdapter(max_tickers=...)`
  로 조정, `None`이면 전 종목 — 매우 느림).

## 모델 설계 요약

- **문제 정의**: 시장 내 횡단면 랭킹 (절대수익 예측이 아닌 상대비교)
- **정규화**: 시장별 percentile rank + 상하위 1% winsorize
- **호라이즌별 가중치**: 단기=모멘텀·수급 중심 / 장기=가치·퀄리티 중심
- **결측 처리**: 없는 팩터는 제외 후 가중치 재정규화 (팩터·카테고리·호라이즌 모든 단계)
  + **데이터 커버리지 페널티**: 유효 팩터 비율 80% 미만 감점, 50% 미만 제외
  (재정규화만 쓰면 팩터 1~2개만 좋은 종목이 상위권을 차지하는 부작용 방지)
- **유니버스 필터**: 시총·거래대금·주가 하한(한국 1,000원 / 나스닥 $5 미만 제외)
  + 한국은 보통주만(우선주 중복 방지)·스팩 제외, 나스닥은 ETF·워런트·유닛 제외
- **팩터 설계 원칙**:
  - RSI는 원값이 아닌 **70 초과분만 페널티** (원값을 쓰면 하락추세가 고득점되어 모멘텀과 충돌)
  - 거래대금 급증은 **주가 방향을 곱해서** 사용 (상승+급증=매수세, 하락+급증=투매)
  - 외국인/기관 순매수는 금액이 아닌 **시가총액 대비 비율**로 사용 (대형주 편향 방지)
  - PER·PBR 음수(적자·자본잠식)는 밸류 팩터에서 제외
- **섹터 표시**: 추천 결과에 업종과 섹터 분포를 함께 표시 (쏠림 육안 점검용,
  점수에는 미반영)

## 점수 예측력 검증 (validate.py)

```bash
python3 validate.py --market KOSPI            # 최근 12개월, 월간 리밸런싱
python3 validate.py --market KOSPI --months 18
```

과거 시점마다 "그때 알 수 있었던 데이터"로 점수를 매기고 실제 이후
20/60/120영업일 수익률과 대조합니다. 매매 시뮬레이션이 아니라 **점수의
예측력 성적표**입니다 (직접 매매 전제이므로 거래비용·체결가 시뮬레이션은 생략).

- **Rank IC**: 점수와 미래수익률의 순위상관. +0.03 이상 일관되면 유의미
- **Top5 초과수익 / 적중률**: 추천 상위 종목이 유니버스 평균을 이겼는가
- **Q5-Q1 스프레드**: 점수 상위 20% − 하위 20% 수익률 차이 (변별력)
- 나스닥은 재무 스냅샷 시점 재현이 불가(yfinance 한계)하므로 참고용

## 데이터 연동 상세

| 항목 | 방식 | 시점 정합성 처리 |
|---|---|---|
| 한국 시세/시총/PER/PBR | pykrx | 기준일 시점 데이터 |
| 한국 재무비율 (ROE 등) | DART `fnlttMultiAcnt` | **법정 제출기한이 지난 보고서만 사용** (사업보고서 3/31, Q1 5/15, 반기 8/14, Q3 11/14). 실제 공시일보다 보수적 → lookahead 없음 |
| 한국 공매도 | pykrx 일별 공매도 비중 | 최근 5일 평균 − 직전 20일 평균. **금지 구간은 자동 NaN** (조회 실패 시 팩터 무효화) |
| 한국 수급 | pykrx 외국인/기관 20일 순매수 | 기준일 시점 데이터 |
| 나스닥 시세 | yfinance 배치 다운로드 | 수정주가 기준 |
| 나스닥 재무/공매도 잔고 | yfinance `.info` | 공매도 변화는 **이전 실행 스냅샷과의 차분** (최초 실행 시 NaN, 2회차부터 유효) |

## 검증 시 주의사항 (필독)

1. **가중치를 백테스트로 튜닝할 때**: 튜닝 기간과 최종 평가 기간을 반드시 분리하세요.
2. **거래비용**: `backtest.py`의 비용 상수는 현재 세율·수수료 기준으로 갱신 후 사용하세요.
3. **백테스트 반복 횟수 기록**: 전략을 수정하며 백테스트를 반복할수록 우연에 적합될 위험이 커집니다.
