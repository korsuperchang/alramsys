# 🏎️ 장난감 자동차 속도 측정기

핸드폰 카메라로 장난감 자동차가 지나가는 속도를 재는 웹 앱입니다.
설치할 앱도, 서버도 필요 없습니다. 브라우저에서 열고 카메라만 허용하면 됩니다.
**영상은 기기 안에서만 처리되며 어디로도 전송되지 않습니다.**

측정 방식은 두 가지이고, 화면에서 바로 바꿀 수 있습니다.

| | 자동 추적 (기본) | 기준선 2개 |
| --- | --- | --- |
| 준비 | 폰만 고정 | 바닥 두 지점 거리를 자로 재고 선을 맞춤 |
| 결과 | 상대 속도(초당 화면폭 배수), 화면 가로 길이를 넣으면 km/h | km/h |
| 강점 | 작은 차·먼 거리에서도 잘 잡힘 | 값이 더 정확함 |

## 자동 추적 원리

화면 전체에서 움직이는 픽셀 덩어리의 중심을 매 프레임 기록하고, 한 번의 통과가 끝나면
위치-시간 표본에 **최소제곱 직선**을 맞춰 기울기를 속도로 씁니다.

- 얇은 선 위에서 정해진 면적을 가려야 하는 문턱이 없어서, 멀리서 찍은 작은 자동차도 잡힙니다.
- 속도는 **초당 화면 폭의 몇 배**(fwps)로 나옵니다. 카메라를 고정해 두면 이 값끼리 그대로 비교되고,
  화면에 담긴 실제 가로 길이를 넣으면 m/s·km/h로 환산됩니다.
- 직선 적합도(R²)와 최소 이동 거리로 흔들림·그림자처럼 제멋대로 움직이는 것을 걸러냅니다.
  화면의 절반 이상이 한꺼번에 달라지면 폰이 흔들린 것으로 보고 버립니다.

## 기준선 2개 원리

화면에 **기준선(게이트) 두 개**를 세워 놓고, 자동차가 각 선을 가리는 순간의 시각을 잡습니다.

```
    A선            B선
     │              │        v = d / Δt
  ───┼──────────────┼───     d  = 두 선 사이의 실제 거리 (자로 직접 측정)
     │   🚗 →       │        Δt = A선 통과 → B선 통과 시간
     │←──── d ─────→│
```

- 배경 차분(background subtraction)으로 "배경과 밝기가 달라진 픽셀"의 비율을 각 선에서 계속 계산합니다.
- 그 비율이 임계값을 넘는 순간이 통과 시점이고, **앞뒤 프레임 사이를 선형 보간**해서 프레임 단위(30fps면 33ms)보다 더 정밀하게 시각을 추정합니다.
- 형태 추적이 아니라 "선을 가렸는가"만 보기 때문에, 자동차 색·모양·조명에 둔감하고 저사양 폰에서도 잘 돕니다.
- 두 게이트 사이를 **실제로 지나왔는지**(가운데 구간의 프레임 간 움직임)까지 확인한 짝만 측정으로 인정합니다.
  이 확인이 없으면 게이트를 한 번 놓쳤을 때 짝이 어긋난 채 고정되어, 이후 측정이 "한 바퀴 도는 시간"으로 잡히고 방향까지 뒤집힙니다.

거리 `d`를 사람이 직접 재서 넣기 때문에, 카메라 캘리브레이션 없이도 물리적으로 정확한 값이 나옵니다.

## 쓰는 법

1. 바닥에 자동차가 지나갈 **직선 구간**을 정하고, 두 지점에 테이프를 붙인 뒤 그 사이 거리를 자로 잽니다. (30~100cm 권장)
2. 앱에 그 거리를 입력합니다.
3. **핸드폰을 고정**하고(삼각대·책·컵 무엇이든), 주행 경로를 옆에서 정면으로 바라보게 둡니다.
4. 화면의 A·B 선을 드래그해서 바닥 표시 지점에 맞춥니다.
5. "배경 학습 중" 표시가 사라지면 자동차를 굴립니다. 두 선을 지나는 순간 속도가 자동으로 뜹니다.

측정값은 km/h, m/s, cm/s로 표시되고 기록이 자동 저장됩니다(최근 50건). `1:64` 같은 축척을 설정하면 "실제 차라면 몇 km/h인지" 환산값도 같이 보여줍니다.

카메라가 없거나 데스크톱에서 동작만 확인하고 싶다면 **데모 모드**를 누르세요. 가상의 자동차가 화면을 지나가며 전체 파이프라인이 그대로 돌아갑니다.

## 정확하게 재는 요령

| 상황 | 대처 |
| --- | --- |
| 값이 들쭉날쭉하다 | 핸드폰이 흔들리는 경우가 대부분입니다. 단단히 고정하세요. |
| 자동 추적이 아무것도 못 잡는다 | 계기판의 **최근 최대**가 **필요**보다 작으면 민감도를 올리세요. 그래도 0.1% 아래면 자동차가 화면에서 너무 작습니다. |
| 아예 감지가 안 된다 (기준선 방식) | **자동 맞춤**을 누르세요. 그래도 "최대 반응"이 1% 아래면 자동차가 화면에서 너무 작습니다 — 카메라를 더 가까이 두거나 감지 구간을 좁히세요. |
| 차가 너무 빨라 그냥 지나간다 | **기준선 두께**를 올리세요. 얇은 선은 프레임 사이에 건너뛸 수 있습니다. |
| 두 기준선이 동시에 계속 켜져 있다 | 폰이 흔들리고 있습니다. 안내에도 그렇게 뜹니다. 고정하세요. |
| 가만히 있는데 계속 잡힌다 | 민감도를 내리세요. 그림자·나뭇잎·형광등 깜빡임이 원인일 수 있습니다. |
| 오차 범위(±)가 크다 | 두 선의 간격을 넓히세요. 통과 시간이 길어질수록 프레임 양자화 오차 비중이 줄어듭니다. |
| 아주 빠른 차 | 60fps 이상을 지원하는 카메라가 유리합니다. 화면에 표시되는 fps를 확인하세요. |

표시되는 `± x.xx km/h`는 프레임 주기에서 오는 시간 분해능 한계를 보수적으로 환산한 값입니다.
(예: 30fps에서 Δt가 250ms면 약 ±13%, Δt가 1초면 약 ±3%)

카메라는 정면(경로에 수직)에서 보는 것이 좋습니다. 비스듬히 보면 두 기준선이 바닥에서 실제로 어디를 가리키는지 어긋나서 계통 오차가 생깁니다.

## 실행

카메라 API는 **HTTPS 또는 localhost**에서만 동작합니다.

```bash
# 로컬에서 확인
cd toycar-speed
npm run serve          # http://localhost:8000
```

### 파일 하나로 쓰기

`standalone.html` 은 CSS·JS가 전부 인라인된 단일 파일이라, 그 파일 하나만 어디에 올려도 그대로 돕니다.
소스는 `index.html` / `css` / `js` 쪽 하나뿐이고, 아래 명령으로 다시 만듭니다.

```bash
npm run build          # standalone.html + dist/artifact.html 생성
```

핸드폰에서 쓰려면 HTTPS로 올려야 합니다. GitHub Pages가 가장 간단합니다:
저장소 **Settings → Pages → Source: Deploy from a branch** 에서 브랜치를 고르면
`https://<사용자>.github.io/<저장소>/toycar-speed/` 로 접속할 수 있고,
브라우저 메뉴의 "홈 화면에 추가"를 누르면 앱처럼 전체 화면으로 실행됩니다(PWA, 오프라인 동작).

## 테스트

감지 엔진은 DOM에 의존하지 않는 순수 모듈이라 합성 프레임으로 검증합니다.

```bash
npm test
```

지나가는 차의 픽셀 속도로부터 기대되는 Δt와 실제 측정값이 프레임 주기 이내로 일치하는지,
정지 화면(노이즈 포함)에서 오검출이 없는지, 방향·가로 게이트·연속 측정이 맞는지,
그리고 게이트를 놓쳐 짝이 어긋났을 때 스스로 바로잡는지 확인합니다.
